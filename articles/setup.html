Router setup

Generally speaking, the main trick to enable client side routing is to configure the server side router to serve content whenever the request gets a 404 HTTP status code. On GitHub Pages, you can achieve this by creating a 404.html file.

It is not required that both files have the same content but you can start by copying your index.html into a 404.html file.

Of course you also need to enable GitHub Pages in your repository settings. You will notice there are two kinds of static websites you can create.

First kind

The first kind applies to repositories named NAME.github.io where NAME is your GitHub username or your GitHub organization name.

In this case the homepage will be https://DOMAIN/
where DOMAIN will default to the repository name NAME.github.io.

You can also set your custom domain, check out the official GitHub Pages documentation.

Second kind

The second kind is when you setup GitHub Pages to any repository; the homepage will be like https://DOMAIN/REPO/ where REPO is your repository name.

In this case it is required that you add a base tag in your HTML head, something like the following: 

<base href="/REPO/" />

To simulate this behaviour locally, the dev server reads the homepage attribute in your package.json.

Example

For instance, this website is of second kind.

It has this base tag:

<base href="/github-pages-router/" />

And the repo package.json has the following homepage attribute: 

"homepage": "https://fibo.github.io/github-pages-router/",
